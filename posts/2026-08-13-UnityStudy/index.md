## 관리되는 메모리
**관리되는 메모리란**
스크립팅 백엔드의 가상 머신에 의해 관리되는 메모리

C#코드의 메모리 할당은 .NET아래에서 돌아가기에 해당 부분에 포함된다.

> 정확하게는 .NET 표준을 구현한 Mono, IL2CPP 런타임 위에서 돌아간다.

> C# 코드의 메모리 할당이 모두 관리되는 메모리는 아니다. 클래스 인스턴스, 배열, 문자열 같은 것들은 관리되는 메모리가 맞지만, NativeArry<T>, Marshal.AllocHGlobal, stackalloc 등 명시적 네이티브, 언매니지드 할당은 C#으로 작성해도 GC 대상이 아니며, 직접 Dispose()해야 한다.

관리되는 메모리는 아래의 영역들로 구성된다.

- 관리되는 힙
- C# 스크립팅 스택
- 네이티브 VM 메모리

### 관리되는 힙
C#에서 발생하는 모든 동적 할당이 이우러지는 영역

관리되는 힙의 할당은 GC에 의해서 관리되며 더 이상 유효하지 않은 객체는 GC에 의해 주기적으로 정리된다.

> GC가 주기적으로 관리 대상 객체를 찾아 메모리를 정리하는 과정을 GC Collect라고 한다.

GC의 관리 대상이 되는 관리되는 할당은 유니티 프로파일러에서 GC Allocatioon, GC.Alloc으로 표시된다.

### 스크립팅 스택
함수 호출과 로컬 변수에 대한 정보를 저장하는 공간

할당과 해제가 매우 빠르며 함수 호출이 종료되면 관련된 할당도 함께 정리된다. 보통 적은 MB의 용량을 사용하는 작고 빠른 메모리 영역이다.

사용량이 많지 않기에 메모리 최적화에서 크게 다루지 않는다.

### 네이티브 VM 메모리
가상 머신 자체를 위해 사용되는 메모리 영역
C# 스크립트를 실행을 가능하게 하는 런타임 환경을 구성하기 위한 할당이라고 할 수 있다.

앱이 C# 스크립트를 실행하려면 가상 머신 프로그램 자체를 위한 메모리가 필요하며, 가상 머신이 C# 스크립트를 구동하는 과정에서 여러 정보를 저장할 메모리 공간도 필요하다.

VM 메모리에 가상 머신 이외에 아래와 같은 정보가 포함된다.

- 리플렉션 정보
- 타입 정보
- 제네릭 타입 테이블

네이티브 VM 메모리 사용량이 클 경우 불필요한 타입 정보가 많다고 판단할 수 있다.
