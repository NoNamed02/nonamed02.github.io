## IOS 메모리 구조와 동작 원리
### 물리 메모리
프로그램이 실행 중에 실제로 접근하는 데이터가 로드되는 공간. 하드웨어적 요소임.

### 가상 메모리
물리 메모리의 사용량은 애플리케이션이 인지하는 메모리 사용량과 다르다.

- 물리 메모리 할당량 != 애플리케이션의 가상 메모리 할당량

애플리케이션은 물리 메모리와 직접 상호작용을 하지 않으며, 애플리케이션의 메모리 할당은 가상 메모리에서 이루어 진다. 즉, 애플리케이션 수준에서는 물리 메모리에 직접 접근할 수 없다.

이러한 가상 메모리를 사용하는 구조에서 프로그래머들은 물리 메모리를 핸들링 할 필요가 없으며, 운영체제는 물리 메모리를 최적화 하여 관리한다.

#### 1. 페이지와 페이지 프레임
가상 메모리는 페이지 = Page 단위로 나누어 관리된다. 일반적으로 모바일은 16KB, PC환경은 4KB이다.

애플리케이션이 사용하는 가상 메모리 사용량은 아래와 같다.

**애플리케이션의 가상 메모리 사용량 = 페이지 개수 * 페이지 크기**


**페이지 프레임 Page Frame**
가상 메모리의 각 페이지는 물리 메모리에 매핑될 수 있으며, 이때 페이지에 대응하는 물리 메모리 구성 단위이다.

#### 2. 페이지 인, 페이지 아웃
페이지를 물리 메모리로 옮기거나 물리 메모리에 올라와 있는 페이지를 물리 메모리에서 제거하는 동작들

- **페이지 인 Paging in**
가상 메모리의 페이지를 물리 메모리의 페이지 프레임에 로드하는 동작

- **페이지 아웃 Paging out**
페이지 프레임을 물리 메모리에서 해제하는 동작

(원도우에는 유사 동작으로 메모리 커밋, 메모리 디커밋이 있다.)

- **예약 Reserve**
바로 사용하지 않지만 이후 사용을 대비해 메모리 공간을 확보해두는 것

- **상주 메모리 Resident Memory**
가상 메모리로 할당된 영역 중 실제로 물리 메모리에 매핑되어 있는 메모리


#### 더티 페이지, 클린 페이지
운영체제에서 페이지 값이 기록된 상태를 기준으로 페이지를 더티, 클린 페이지로 구분한다.

만약 size가 3인 array에 [0]에만 값을 할당 했다면 첫 페이지만 더티 페이지이고 나머지는 클린 페이지로 구분된다.

#### 1. 더티 페이지 Dirty Page
프로세스가 실제로 값을 할당한 페이지, 데이터가 변경된 페이지이다.

변경된 값을 유지해야 하기 때문에 운영체제가 임의로 페이지 아웃 하는것은 불가능 하며, 물리 메모리에 상주하게 된다.

#### 2. 클린 페이지 Clean Page
읽기 전용으로 매핑된 데이터를 저장하거나 아직 하번도 쓰기 접근이 발생하지 않은 페이지이다.

운영체제가 물리 메모리가 부족한 상황이면 페이지 아웃 할 수 있다.

페이지 아웃된 클린 페이지는 접근이 발생할 시 원본 파일이나 바이너리에서 데이터를 로드하여 물리 메모리로 페이지 인 된다.

### 메모리 풋 프린트 Memory Footprint
앱이 실제로 사용 중인 메모리의 규모를 나타내는 지표

IOS는 메모리 풋프린트를 아래와 같이 정의한다

- 메모리 풋프린트 = 더티 메모리(더티 페이지 합산) + 압축된 더티 메모리
(메모리 풋 프린트 계산에서 압축된 더티 메모리의 경우 압축 전 크기로 계산된다.)

이때 더티 페이지를 생성하는 특성에 따라 3가지 유형으로 나뉜다.

- 더티를 유발하는 할당
- 더티를 만들지 않는 할당
- 압축된 더티로 전환될 수 있는 할당

#### 1. 더티를 유발하는 할당
- 힙 할당 후 값 쓰기
- 그래픽 리소스 = Metal
- 심볼이 수정된 프레임 워크
- 런타임 메타데이터

힙에 할당된 메모리는 실행 중에 객체가 생성되고 값이 변경된다.
GPU가 사용하는 그래픽 리소스는 렌더링을 위해 매 프레임 접근이 이루어 진다.
원본과 다른 프레임 워크는 수정 값을 유지하기 위해 물리 메모리에 유지된다.

위와 같은 할당은 상주 메모리에 머무를 가능성이 크다. 잦은 접근이 이루어 지고 실행중에 값이 변경되기에 상주 메모리에서 해제가 되기 어렵다. 결과적으로 더티 페이지를 지속적으로 유발한다.

#### 2. 더티 페이지를 만들지 않는 할당
- 읽기 전용 코드와 프레임 워크
- 읽기 전용 데이터
- read-only 매핑 파일

클린 메모리에 사용 중에는 상주 메모리를 차지할 수 있지만, 메모리가 부족해지면 쉽게 물리 메모리에서 해제할 수 있기에 메모리 풋프린트에 포함되지 않는다.

클린 메모리의 크기가 지나지게 클 경우 물리 메모리에서 해제와 재로딩이 반복될 수 있으며, CPU 처리 속도가 느려질 수 있다.

#### 3. 압축된 더티
접근 빈도가 낮은 더티 페이지를 운영체제가 물리 메모리 내에서 압축해 둔 메모리이다.

해당 메모리 주소에 다시 접근할 시 압축을 해제하고 사용된다.

#### 4. 상주 메모리 != 메모리 풋프린트
측정된 메모리 풋프린트와 상주 메모리는 다른 개념이며 크기 또한 달라질 수 있다.

- **상주 메모리**
현재 물리 메모리에 상주한 메모리의 크기

- **메모리 풋프린트**
더티 메모리와 압축된 더티 메모리의 합

메모리 풋프린트에 포함되지 않는 클린 메모리도 상주 메모리에 올라갈 수 있기때문에 주의가 필요하다.

> **왜 IOS는 메모리 풋프린트를 기준으로 사용하는가?**
상주 메모리는 물리 메모리에 올라와 있는 페이지의 합이지만, 운영체제의 페이지 인, 아웃에 따라서 값이 유동적으로 변하기에 측정이 어렵다. 즉, 앱이 반드시 유지해야 하는 메모링 사용량을 정확하게 파악하기 어렵다. 메모리 풋프린트는 페이지 아웃이 불가능하기에 항상 유지되는 값이다.

#### IOS 메모리의 한계
IOS는 메모리 사용량이 증가하면 다음과 같은 순서로 메모리를 정리한다.

- 클린 페이지의 페이지 아웃
- 다른 프로세스의 클린 페이지 정리
- 백그라운드 프로세스 종료

이후 메모리가 부족한 경우 실행중인 앱을 OOM = Out Of Memory 에러와 함께 강제 종료 시킨다.
