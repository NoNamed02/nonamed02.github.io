### 그래픽스 명령어
**그래픽스 명렁어란?**
GPU가 렌더링과 관련된 작업을 수행하도록 지시하는것. 보통 그래픽스 드라이버 API를 통해 실행, GPU로 업로드 된다.

여러 그래픽스 API들이 사용하는 명령어들
- **Draw Call**
도형을 그리도록 요청

- **Clearing**
프레임 버퍼를 초기화

- **블렌딩 설정**
알파 블렌딩 방식등을 설정하여 색상 조합 방식을 지정

- **버퍼 설정 및 텍스처 설정**
버퍼와 텍스처를 GPU에 전달, 상태 설정

- **렌더 파이프라인 상태 설정 = Set Render Pipeline State**
드로우 콜을 발행하기 전에 적용할 파이프라인 상태를 지정

CPU에서 생성된 그래픽스 명령어는 명령어 버퍼 *= Command Buffer*에 담겨 GPU로 전송된다.

그래픽스 명렁어를 어떤 순서로 실행하는 가에 따라서 렌더링 성능 최적화를 유도할 수 있다.(셰이더를 설정 후 상태를 유지하고 여러 드로우 콜을 실행하는 방식)

### 렌더 파이프라인 상태
**GPU의 렌더 파이프라인 상태**
GPU가 렌더링을 수행하는 데 필요한 다양한 설정과 구성 요소를 하나로 묶어둔 상태
(EX - 드로우콜이 실행되어 메시를 그리기 전, 해당 메시가 어떤 셰이더를 사용할지 미리 결정을 해야한다.)

이하와 같은 요소들이 포함된다.

- 셰이더 프로그램
드로우에 사용할 쉐이더등을 설정

- 블렌드 모드
프레임 버퍼에 있는 내용과 렌더링 결과물을 어떤 방식으로 혼함할지 결정

- 스텐실 모드, 깊이 테스트 모드
서로 겹치는 오브젝트를 어떤 순서로 그릴지 어떤 방식으로 보여주거나 숨길지를 결정

- 렌더 타겟
렌더링 결과가 저장될 위치를 결정

각각의 드로우 콜들은 미리 설정한 렌더 파이프라인 상태를 기준으로 그려진다. 즉, 각각의 드로우 콜들은 렌더 파이프라인 상태의 하위에 존재한다고 이해할 수 있다.

서로 다른 블렌드 모드나 다른 쉐이더 혹은 렌더 타깃을 바꾼다면 GPU가 현재 사용중인 렌더 파이프라인 상태를 다른 상태로 전환한 뒤 드로우 콜을 실행해야 한다는 의미이다. 이런 상태 전환이 자주 이루어 지면 성능에 부정적인 영향을 미친다.

### 렌더링 병목의 이해
렌더링 과정에서 이하와 같은 병목을 예측할 수 있다

- CPU가 그래픽스 명령어를 구성하는 과정에서 발생하는 지연
- CPU에서 GPU로 명령어 버퍼와 리소스를 업로드 하는 과정에서 발생하는 지연
- GPU 내부에서 그래픽스 처리가 수행되는 과정에서 발생하는 지연
