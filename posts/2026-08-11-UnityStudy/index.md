## 유니티의 메모리 구조

### 가상 메모리 할당 분포
아래는 유니티 앱이 가상 메모리 상에서 차지하는 할당을 크게 5가지 유형으로 나눈것이다.

1. 바이너리
2. 유니티 네이티브 메모리
3. 유니티 관리되는 메모리
4. 그래픽스
5. 네이티브 플러그인

#### 바이너리
앱 실행 파일이라고 불린다.
앱 실행에 필수적인 코드와 라이브러리를 포함하는 파일이다. 변경될 수 없는 읽기 전용 정적 코드이며 클린 메모리에 해당한다.

#### 유니티 네이티브 메모리
유니티 엔진의 CPP구현에 의해서 발생하는 할당이다. C# 그래픽 객체를 로드시 유니티 내부에서 CPP 그래픽 객체를 생성한다. 이때 생성되는 CPP 객체 할당이 유니티 네이티브 메모리 할당에 해당한다. 더티 메모리에 속한다.

#### 유니티 관리되는 메모리 Managed Memory
C#을 포함하는 .NET 관리 코드에 의해 발생하는 할당이 해당 영역에 포함된다.
대표적 예시로 C# 코드에서 수행한 힙 할당이 해당된다. 유니티의 C# 스크립트 실행 과정에서 발생하는 할당도 이 영역에 포함된다.

#### 그래픽스
GPU가 사용되는 것들, 셰이더 프로그램, 텍스쳐 등 그래픽스 리소스가 해당된다.
매 프레임 접근하기에 더티 메모리에 해당한다.

애플의 경우 CPU, GPU가 시스템 메모리를 공유하기에 GPU에 있는 그래픽 리소스가 시스템 메모리에 상주한다. 원도우는 GPU 전용 메모리를 사용하기에 GPU로 업로드한후 할당 해제된 경우 GPU에만 리소스가 존재한다.

#### 네이티브 플러그인
유니티 프로젝트에 포함된 네이티브 플러그인 바이너리이다.
읽기 전용 코드이기에 클린 메모리로 분류된다.

플러그인 실행 과정에서 수행되는 동적 할당은 더티 메모리에 할당되는 주의점이 있다.

### 엔진의 메모리 구조
**유니티의 구조**
CPP로 구현된 코어를 C#을 통해 제어하는 게임엔진이다. C#으로 구현한 객체는 .NET 객체이기 때문에 유니티는 CPP로 구현된 코어를 .NET 가상 머신을 통해 제어하는 엔진라고 할 수 있다.

위의 구조를 기반으로 유니티의 코드는 2개의 계층으로 구분할 수 있다.

- 네이티브 코드 = CPP
- 관리되는 코드 = C#

> 가상 환경 언급
저자가 언급하는 가상 환경은 흔히 사용하는 운영체제 시뮬레이션과는 다르다. 책에는 이하와 같이 적혀있다.
"C#과 같은 고수준 언어가 하드웨어와 독립적으로 실행될 수 있도록 중간 계층을 제공하는 프로그램"
C#코드를 컴파일하면 플랫폼에 종속되지 않는 중간 언어로 변환되고 가상 머신은 이 중간언어를 해당 시스템의 네이티브 코드로 변환하여 C#코드가 각 운영체제에 맞게 작동하도록 한다.
가상머신은 이하와 같은 역할도 한다.
1. 타입 안정성 보장
실행 중인 코드의 타입을 검사해 코드 안정성을 보장한다.
2. 메모리 관리
개발자가 직접 메모리를 해제하지 않아도 가비지 컬렉션을 통해 메모리를 관리한다.
직관적 표현으로 가상 머신은 C#을 실행하는 엔진이다. C#, .NET 코드는 가상 머신에 의해 관리되기에 관리되는 코드라고 표현한다.

유니티에서 사용되는 **관리되는 메모리**나 **관리되는 코드**라는것은 .NET 가상 머신에 의해 자동으로 관리되는 코드와 메모리를 의미한다. 유니티는 가상 머신을 C#을 실행하는 프레임워크라는 의미에서 스크립팅 백엔드라고 부른다.

유니티는 아래의 2가지 스크립팅 백엔드를 제공한다

- Mono
- IL2CPP

유니티에서 스크립팅 백엔드를 Mono로 사용할시 Mono 컴파일러가 C#을 IL 코드로 컴파일하고 이후 Mono 가상 머신이 런타임에 IL 코드를 기계어로 변환해 실행한다.

IL2CPP의 경우 C#을 IL 코드로 컴파일 후 CPP로 변환하여 CPP코드를 기계어로 컴파일한다. 해당 방식은 런타임에 IL을 기계어로 변환하는 과정이 없어 일반적으로 Mono 벡엔드 보다 CPU 처리 성능이 우수하다.

해당 이유로 Mono보다 IL2CPP 벡엔드를 사용하는 것이 권장된다. 다만 CPP코드를 거쳐 네이티브 코드를 생성해야 하기에 빌드 시간이 더 걸릴 수 있다.


대부분 빌트인 유니티 오브젝트는 CPP 구현과 C# 구현을 모두 가지고 있다.
(C#코드에서 게임 오브젝트를 인스턴스화 시키면 CPP 버전 게임 오브젝트가 같이 생성된다.)

유니티는 관리되는 게임 오브젝트와 네이티브 게임 오브젝트를 인스턴스 ID, 포인터와 같은 내부 식별자로 서로 바인딩한다.

CPP 기반 유니티 오브젝트 타입은 사용자가 직접 접근하는 것이 불가능하다. C# 스크립트가 C# 게임 오브젝트를 참조하여 사용할때 내부적으로 연결된 CPP 게임 오브젝트에 구현된 기능을 호출한다. 즉, C# 오브젝트를 통해 간접적으로 CPP로 구현된 게임 오브젝트를 사용하는 구조이다.

즉, 1개의 오브젝트에 네이티브 오브젝트 = CPP, 관리되는 오브젝트 = C#이 함께 존재하기에 유니티의 메모리 영역도 아래와 같이 2가지로 구분한다.

1. 관리되는 메모리
.NET 가상 머신에 의해 자동으로 관리되는 영역
2. 네이티브 메모리
유니티 엔진의 CPP 코드가 사용하는 영역
