### 관리되는 힙 동작 방식
#### 관리되는 힙과 세그먼트
new 키워드로 만든 인스턴스, C# 타입 유니티 컴포넌트를 생성시 해당 객체들은 관리되는 힙 영역에 할당된다. 관리되는 힙은 페이지 단위를 직접 다루지 않고 세그먼트라고 부르는 더 큰 단위를 사용한다.

> 세그먼트는 블록이라고 불리기도 한다.

하나의 세그먼트는 연속된 여러 개의 페이지로 구성되며 하나의 세그먼트에는 하나 이상의 오브젝트가 할당될 수 있다.

유니티에서 관리되는 힙은 여러 대의 세그먼트로 이루어진다.

#### 새 할당 발생
관리되는 힙에서 새로운 할당이 발생하는 GC는 다음 순서로 할당할 수 있는 공간을 찾는다.

1. 기존 세그먼트 내부에서 연속된 빈 공간을 검색
2. 충분한 공간이 있으면 해당 공간을 사용
3. 공간이 부족하거나 조각화가 많이 존재할시 새로운 세그먼트를 운영체제로부터 예약해 힙을 확장

#### GC 컬렉션 실행
GC가 작동하면 참조가 없어 유효하지 않은 오브젝트는 제거된다.

하지만 GC가 작동하여 정리를 하더라도 오브젝트가 존재하던 페이지는 아래의 이유로 운영체제 관점에서는 더티 페이지로 판정하며 물리 메모리에 남는다.

1. 해당 페이지는 값이 기록이 되었기에 운영체제 기준에서는 더티 페이지로 분류
2. GC는 죽은 오브젝트가 차지하던 공간을 재사용 가능 상태로 표시만함

> 내부적으로 GC가 죽은 오브젝트가 있던 공간을 free list에 기록하여 이후 할당시 재사용함

이로 인해서 GC가 수행되더라도 네이티브 프로파일러에서 더티 메모리 크기는 거의 줄어들지 않는다. GC는 논리적 정리를 행할뿐, 물리 메모리를 즉시 반환하지는 못하기 때문이다.

> GC는 메모리를 물리적으로 비우고 운영체제에 반환하는 것이 아닌, 사용되던 메모리 공간을 다른 오브젝트 할당에 재사용하는 방식으로 동작한다.

> **유니티에서 관리되는 힙의 가상 메모리 사용량**
유니티의 관리되는 힙은 한 번 예약한 가상 메모리 공간을 줄이지 않는다. 가상 메모리 할당량은 런타임 동안 증가만 가능하며 감소는 불가능하다(리맵 과정을 사용하면 메모리 사용량을 감소시킬 수 있다). 해당 방식은 힙의 가상 메모리 예약 크기를 줄이지 않는 대신 장기간 사용되지 않은 물리 메모리를 점진적으로 반환하는 구조를 가진다. 이는 Boehm GC를 사용하는 다른 런타임들도 공통으로 가지는 특징이며, 유니티 GC도 Boehm GC를 사용해 구현되었다.

#### GC 이후 새 할당이 발생시
아래 규칙에 따라 세그먼트의 빈 공간에 새로운 오브젝트가 할당된다.

1. 죽은 오브젝트가 차지하고 있던 페이지도 빈 공간으로 간주해 재사용
2. 할당 크기에 맞는 연속된 빈 공간이 있으면 해당 공간을 즉시 재사용
3. 연속 공간이 부족할시 다른 세그먼트를 탐색
4. 세그먼트가 없다고 판단될시 새로운 세그먼트를 예약해 힙을 확장

만약 작은 빈 메모리 공간이 많이 남을시 메모리 단편화 문제가 발생할 수 있다.

> **메모리 단편화**
파편화된 빈 메모리 공간이 여러 메모리 주소에 흩어져 있어서 메모리의 빈 공간을 효율적으로 사용하지 못하는 현상

#### 해제 후 리맵
여러 차례 GC가 수행된 후에도 계속 비어 있는 세그먼트가 남아 있다면 세그먼트를 해제 한 뒤에 새로운 빈 세그먼트를 다시 재할당하는 방식으로 물리 메모리에 남아 있던 더티 페이지를 완전히 해제한다.

논리적으로 비어 있지만 더티 페이지가 남아있는 경우 세그먼트를 제거한 뒤 새로운 세그먼트를 동일 크기로 생성하여 정리한다.

> 리맵이 발생하는 주기는 유니티 버전에 따라 다르다. 유니티 6 기준으로는 GC가 6번 실행될 때마다 리맵이 수행된다.

다만, 세그먼트가 비어 있다고 항상 죽은 세그먼트인 것은 아니며 GC가 정리한 직후 사용될 가능성이 많다. 이때 리맵이 발생한다면 일시적으로 비어있는 세그먼트까지 해제할 가능성이 높다. 이는 결과적으로 CPU 자원을 낭비하는 결과로 이어진다.

> **왜 오브젝트가 제거될 때마다 세그먼트를 바로 릴리즈하지 않는가?**
오브젝트가 소멸했다고 즉시 해당 공간을 차지하던 페이지를 운영체제에 반환하면 이후 다음 할당에서 다시 새로운 페이지를 운영체제에 요구해야 한다. 이 사이에서 페이지 인 아웃이 발생하며 이는 성능 부하로 이어질 수 있다. 이러한 이유로 대부분의 소프트웨어는 한번 확보한 가상 메모리를 GC가 즉시 정리하지 않는다.
